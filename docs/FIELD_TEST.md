# Waffer Field Test Protocol

> راجع أيضًا `docs/LAUNCH_READINESS.md` لمعرفة موانع الإطلاق الحالية، و`docs/FIELD_TEST_AUTOMATION.json` لمعرفة ما تغطيه المحاكاة الآلية.

هذه الخطة مخصصة لمرحلة `field-test` الحالية، ولا تعني جاهزية الإطلاق التجاري.

## قبل كل اختبار

- افتح النسخة المنشورة حديثًا مع `?debug=1`.
- استخدم **لوحة الاختبار الميداني** لاختيار السيناريو وتسجيل `PASS` أو `FAIL` أو `PENDING` مع الملاحظات.
- عند وجود تحليل فعلي، استخدم **حفظ الحالة مع دليل التحليل الحالي** لالتقاط Analysis ID وcommit وهوية السيارة وحالة الكتالوج.
- بعد إكمال جلسة الاختبار استخدم **تصدير مسودة الأدلة**. المسودة تحفظ محليًا ولا تغيّر بوابة الإطلاق الرسمية.
- افحص المسودة بالأمر `npm run validate:field-test-draft -- <draft.json>` قبل تحويلها إلى نتائج رسمية.
- لا تُحدّث `docs/FIELD_TEST_RESULTS.json` إلى `PASS` إلا بعد مراجعة الدليل.
- بوابة الإطلاق تعيد التحقق من أدلة الملف الرسمي نفسه في كل CI؛ كتابة `PASS` يدويًا بلا `testedAt`/دليل صالح لن تتجاوز البوابة.
- لا تغيّر `launchPhase` من `field-test` إلى `public-beta` أو `production` قبل أن تصبح السيناريوهات العشرة كلها `PASS`؛ CI سيفشل تلقائيًا إذا حدث ذلك.
- تأكد أن حالة الخدمة تظهر `mvp-2026-09` ومعرف commit.
- لا تستخدم مستندًا يحتوي بيانات شخصية غير ضرورية.

## السيناريوهات

| # | السيناريو | المتوقع |
|---|---|---|
| 1 | صورة JPG واضحة بدون VIN | استخراج البنود، بقاء توافق الكتالوج غير مطبق |
| 2 | صورة هاتف أكبر من 3MB | تحسين الصورة تلقائيًا ثم التحليل |
| 3 | PDF أقل من 3MB | تحليل مباشر دون ضغط |
| 4 | PDF أكبر من 3MB | رفض واضح قبل الإرسال |
| 5 | VIN صحيح + عرض قطع | ظهور Vehicle ID ثم بدء الكتالوج |
| 6 | VIN غير صحيح | منع التحليل المرتبط بالكتالوج ورسالة تحقق واضحة |
| 7 | عرض يحتوي قطع + أجور + خدمات | مطابقة القطع فقط وتخطي العمل/الخدمات |
| 8 | فحمات/أقراص أمامية أو خلفية | استخدام Fitting Position عندما يوفره الكتالوج |
| 9 | عرض بلا أرقام قطع | انخفاض ثقة الهوية والسعر وعدم اختلاق أرقام |
| 10 | عرض فيه إجمالي لا يطابق مجموع البنود | ظهور فرق حسابي يحتاج مراجعة |

## معايير النجاح

لكل سيناريو سجّل:

- Analysis ID
- engineVersion
- commit المنشور
- نوع الملف وحجمه قبل/بعد التحسين
- عدد البنود المستخرجة
- عدد بنود القطع
- عدد البنود التي طابقها الكتالوج
- زمن مطابقة الكتالوج
- نتيجة Front/Rear إن كانت مطلوبة
- هل الإجمالي المطبوع مطابق للمجموع المستخرج؟
- أي بند قرأه النظام خطأ

## معيار نجاح النسخة قبل الانتقال إلى التسعير

- لا يوجد Crash أو تعليق غير محدود في السيناريوهات العشرة.
- الصور الكبيرة تُعالج أو تُرفض برسالة واضحة.
- لا تتم مطابقة labor/service/fee كقطع.
- لا يُختلق رقم قطعة أو سعر سوق.
- VIN الصحيح يحدد السيارة في الحالات المدعومة.
- فشل الكتالوج لا يمنع ظهور نتيجة تحليل العرض.
- نتيجة AI تحافظ على عقد البيانات وتمر CI.
- أي خطأ قابل لإعادة التتبع عبر Analysis ID + commit.

## تقرير الخطأ

في وضع `?debug=1` يوجد مساران منفصلان:
- **تصدير تقرير الاختبار**: تقرير تشخيصي لتحليل واحد.
- **تصدير مسودة الأدلة**: ملف يجمع حالات السيناريوهات العشرة والأدلة التي حُفظت محليًا.

المسودة المصدرة لا تصبح دليل إطلاق رسميًا إلا بعد مرورها عبر Validator ومراجعة محتواها. لا حاجة لإرسال ملف عرض الصيانة نفسه إلا إذا كان الخطأ متعلقًا بالاستخراج من المستند.


## بوابة الترقية

- أثناء `field-test`: يسمح CI باستمرار التطوير إذا كان ملف النتائج سليم البنية حتى مع وجود حالات `PENDING` أو `FAIL`.
- عند محاولة الانتقال إلى `public-beta` أو `production`: يجب أن تكون السيناريوهات العشرة كلها `PASS`.
- يتم تنفيذ هذا الشرط عبر `npm run gate` ضمن `npm run ci`.
- هذا يمنع اعتبار النسخة جاهزة للإطلاق اعتمادًا على نجاح البناء وحده دون دليل اختبار ميداني.

## التحقق من مسودة الأدلة

الأمر:

```bash
npm run validate:field-test-draft -- path/to/waffer-field-test-draft.json
```

يتحقق من:
- وجود السيناريوهات 1–10 مرة واحدة فقط.
- صحة حالات `PASS/FAIL/PENDING`.
- وجود `testedAt` للنتائج المنفذة.
- وجود Analysis ID وengineVersion وcommit في السيناريوهات التي تعتمد على تحليل فعلي.
- أن السيناريو 5 يحتوي Vehicle ID وVIN صالحًا وحالة كتالوج مكتملة.
- أن السيناريو 9 يثبت عدم وجود أرقام قطع معرّفة.
- أن السيناريو 10 يحتوي فرقًا فعليًا بين الإجمالي المطبوع والمحسوب.
- أن حالات `FAIL` تحتوي ملاحظات تشرح المشكلة.

نجاح الـValidator لا يغيّر `docs/FIELD_TEST_RESULTS.json` تلقائيًا؛ التحويل إلى نتيجة رسمية يبقى خطوة مراجعة مقصودة.
