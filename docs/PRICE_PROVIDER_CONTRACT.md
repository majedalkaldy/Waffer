# Waffer Trusted Price Provider Contract

هذا العقد يفصل **مصدر السعر** عن منطق «وفّر» الأساسي. السوق الحالي السعودية، لكن العقد لا يفترض مزودًا أو دولة ثابتة.

## الحالة الحالية

لا يوجد Price Provider إنتاجي متصل حاليًا. لذلك يجب أن تبقى النتيجة:

- `marketPrice = null`
- `bestOffer = null`
- `saving.status = NOT_CALCULATED`
- `verifiedMarketPricing = false`

إضافة هذا العقد لا تعني أن «وفّر» يملك أسعار سوق الآن.

## نوعا بيانات السعر

### 1. Market Range

نطاق إحصائي للسوق:

- `min`
- `median`
- `max`
- `currency`
- `sampleSize` إن توفر

يُستخدم لعرض نطاق السوق فقط. **لا يُستخدم وحده لحساب التوفير المؤكد.**

يجب أن تكون القيم أرقامًا غير سالبة وبالترتيب:

`min <= median <= max`

ويجب أن تطابق العملة عملة السوق التي يحددها `market-config`.

### 2. Verified Offer

عرض شراء فعلي يمكن استخدامه للمقارنة المباشرة. لا يُقبل إلا إذا تحقق كل ما يلي:

- رقم القطعة يعادل رقم القطعة المطلوب بعد تطبيع التنسيق.
- `verifiedIdentity = true`.
- `vehicleVerified = true`.
- `inStock = true`.
- العملة تطابق عملة السوق.
- `finalUnitPrice` رقم صالح وغير سالب.
- اسم البائع موجود.
- رابط الدليل `sourceUrl` يستخدم HTTPS.
- توجد قيمة `checkedAt` صالحة لتتبع وقت التحقق.

`finalUnitPrice` يجب أن يمثل السعر النهائي للوحدة الذي سيستخدم للمقارنة، وليس سعرًا ناقصًا معروفًا أنه يحتاج رسومًا إلزامية أخرى.

## قاعدة التوفير

لا يحسب «وفّر» التوفير من median أو min أو max.

التوفير يحسب فقط عند وجود Verified Offer صالح:

`workshop total - verified offer total`

إذا لم يكن الفرق موجبًا، تكون القيمة 0 والحالة `NO_POSITIVE_SAVING`.

إذا لم يوجد عرض موثّق، تبقى القيمة null والحالة `NOT_CALCULATED`.

## سلوك فشل المزود

فشل الشبكة أو المزود لا يسمح بالتخمين:

- `PROVIDER_ERROR`: مزود متصل لكنه غير متاح.
- `PROVIDER_TIMEOUT`: المزود تجاوز مهلة الاستجابة المحددة؛ لا يتم عرض سعر أو توفير.
- `NO_VERIFIED_PRICE`: المزود استجاب لكن لم يقدم بيانات تحقق العقد.
- `INSUFFICIENT_IDENTITY`: هوية القطعة أو السيارة غير كافية، ولا يتم استدعاء المزود.
- `NOT_CONFIGURED`: لا يوجد مزود إنتاجي للسوق.

## واجهة المزود

كل adapter يجب أن يعرّف:

- `id`: معرف ثابت للمزود.
- `label`: اسم المصدر المعروض.
- `lookup(input)`: دالة تعيد بيانات المصدر الخام.

المدخل يحتوي السوق واللغة والعملة وهوية القطعة والسيارة والكمية، إضافة إلى `signal` من نوع AbortSignal. يجب على أي adapter يستخدم fetch تمرير هذه الإشارة إلى طلبه الخارجي حتى يمكن إيقافه عند انتهاء المهلة.

تقوم `lib/price-provider.js` بالتحقق النهائي من المخرجات؛ لا يحق للـadapter تجاوز قواعد الثقة.

## إضافة مزود جديد لاحقًا

عند اختيار مزود:

1. إنشاء adapter مستقل خاص بالمزود.
2. إضافة الاختبارات الخاصة به.
3. تسجيله للسوق في price provider registry.
4. إبقاء مفاتيح API في Vercel Environment Variables فقط.
5. اختبار الفشل/timeout/rate limit وعدم تسريب الأسرار.
6. عدم تفعيل `verifiedMarketPricing` إلا بعد اجتياز الاختبارات الحية.

أي اشتراك أو تكلفة مزود خارجي تبقى قرارًا منفصلًا قبل التفعيل.
